# Exterior construction qualification

Exterior scenery is generated from domain-separated scene and parcel seeds. The primary room, its cameras, adjoining room and finite sky closure keep their existing ownership and bounds. Exterior meshes retain the `#exterior` tag and remain excluded from primary-room O-voxel geometry.

The neighborhood program controls building probability (0.25–0.88), footprint scale (0.9–1.85), orientation, walkway width (0.65–2.05 m), paving pitch (0.28–1.30 m), and railing frequency. Window-directed proposals and a bounded rejection loop place at most 18 separated parcels. Buildings and planting stay clear of the room and its walkways. Larger plots are attempted first; smaller plots can fill remaining valid space.

Building programs vary connected wings, storey count and height, selective upper setbacks and offsets, flat/parapet/pitched/shed roofs, rooftop equipment, facade substrate, bay spacing, pane aspect, frame width, stagger, mullions, fins and sun hoods. Slenderness and minimum wing-width constraints avoid implausibly thin towers. The roof-height bound includes the finite annotation background. Pane widths reserve both jambs and a joint between bays; mullion end caps embed into the surrounding frame, preventing coincident glass/metal faces. Exterior walls use mineral, paint, terracotta, timber or metal finishes. Six shared finish slots per supported substrate vary pigments, texture phase and roughness without per-building textures. Distant windows are backed opaque dielectric facade proxies, with varied tint and roughness; these are not modeled building interiors.

Gardens combine grounded branching plants, shrubs and bamboo, with varied height, footprint, position and yaw. Courtyards retain benches and pergolas. Plant meshes use the plant semantic class. Context ground and paving use independent bounded exterior finish choices.

Dataset distribution exports include parcel counts, near-window context fraction, building probability, parcel scale, walkway width, building width/depth, storey count/pitch, roof type (0 parapet, 1 pitched, 2 shed), wing count, bay pitch, requested window-width fractions, window-height fractions and distance. Actual aperture width is capped by the frame-and-joint clearance budget. The window-normal metric is approximate placement coverage, not measured rendered visibility.

## Reproducing the local CPU audit

Build the library test executable, then run `exterior_population_qualification --ignored --exact` using its fully qualified test name, or filter `exterior_population_qualification --ignored`. Outputs go to the ignored local directory `out/exterior_diversity/`. The audit constructs 64 mixed rooms, validates layouts and complete meshes, records realized programs and construction timings, verifies exterior tags, and generates flat-shaded CPU contact sheets from production geometry. Separate ordinary tests cover 256 building programs, deterministic replay, bounded geometry, material resolution and 128-room parcel/sky/clearance checks. A signed vertical mesh sweep verifies continuous parapet support; grounded plants must enter the soil surface. The existing coplanar-face audit also includes exterior window frames, using a translation-stable area calculation for small distant geometry.

The preview sheets are geometry diagnostics, not PBR renders. Exact mesh hash uniqueness does not establish perceptual diversity or downstream learning utility. CPU component timings do not measure end-to-end GPU generation throughput. GPU captures, macOS/WebGPU appearance and concurrent-training throughput require a separate qualification window.
